# SheRuntime（她律）产品说明与体验指南

## 一、产品介绍

SheRuntime（她律）是一套个人身体学习系统，由 iOS App 和圆形智能硬件组成。

产品将三类信息放进同一条身体时间线：

- Apple Watch / HealthKit 提供的客观身体信号；
- 圆形硬件记录的当下主观感受；
- 手机端补充的语音、文字和生活事件上下文。

我们希望帮助用户逐渐发现自己的身体规律，例如：自己通常在什么时间更有能量、哪些生活情境更常与疲惫同时出现，以及今天的状态与过去的自己相比发生了什么变化。

SheRuntime 是个人学习工具，不是医疗诊断或健康决策工具。产品不会给出医学结论，也不会用人群平均值要求用户，而是帮助用户基于自己的长期数据进行回顾和理解。

## 二、产品要解决的问题

### 1. 身体信息彼此割裂

现有健康产品可以记录睡眠、心率、HRV、步数等数据，但这些数据通常与用户当时的感受、工作状态和生活事件相互分离。用户看到的是一组组数字，却很难理解数字背后发生了什么。

### 2. 主观感受难以及时记录

疲惫、紧张、专注或精力充沛等感受往往转瞬即逝。传统记录方式步骤较多，用户很难在感受发生的当下留下信息。

### 3. 通用指标难以解释个人状态

同一个指标对不同人的意义可能不同。单纯使用“正常值”或人群平均值，很难准确描述一个人的真实状态。

### 4. 身体数据与 AI 结合时存在隐私问题

身体数据属于敏感数据。如果引入大语言模型，就必须明确哪些数据会被发送、模型依据什么回答，以及谁能够访问模型服务。

## 三、解决方案

SheRuntime 通过“客观信号 + 主观感受 + 生活上下文”建立个人身体时间线。

### 1. 客观身体信号

iOS App 读取 Apple Watch / HealthKit 中的睡眠、HRV、静息心率、活动等数据，并以个人近期数据作为参照，形成能量地图和状态变化趋势。

### 2. 低门槛主观记录

用户可以通过圆形硬件或手机语音入口快速记录当下感受。语音在手机端完成转写，用户确认或编辑后进入个人时间线。

### 3. 个人身体时间线

系统把身体指标、主观感受以及会议、工作、运动、情绪等事件放在一起，使用户能够从时间维度回顾身体变化。

### 4. 本地优先的个人问答

对于“我今天走了多少步”“昨晚睡了多久”“今天记录了几条”等确定性问题，系统优先从设备本地数据直接回答，不调用大语言模型。

当问题需要综合归纳时，系统会检索本地身体知识，并在获得授权的情况下调用大语言模型。回答中会说明使用了设备本地数据、本地知识还是大语言模型。

### 5. 产品表达原则

- 只与用户自己的历史状态比较，不与人群比较；
- 只描述“通常对应”“更常出现”的规律，不把相关性写成因果；
- 所有结果仅供个人回顾和学习，不作为医学结论。

## 四、现场完成内容

本次现场完成并打通了以下内容：

1. 完成“今日、地图、洞察、问问、我的”五个核心页面，以及中英文文案体系。
2. 完成可直接通过浏览器访问的 Web App Demo，用于展示完整产品概念和主要交互流程。
3. 完成 iOS 端 HealthKit 授权和真实数据读取，可基于个人数据计算并展示能量地图。
4. 完成手机语音采集、系统语音转写、内容确认和编辑流程。
5. 完成圆形硬件与 iPhone 的 BLE 连接，以及真实麦克风音频流的接收。
6. 完成语音记录进入设备本地时间线，并参与本地问答和个人上下文组织。
7. 建立本地身体指标知识库和检索能力。
8. 完成本地优先的问答路由：确定性问题在设备端回答，需要综合归纳时再调用大语言模型。
9. 完成 DeepSeek 服务端代理、结构化输出校验、超时与错误处理。
10. 完成服务的 HTTPS 部署和 API Key 鉴权，使大语言模型密钥不会直接出现在客户端中。

## 五、使用方法

产品提供两种体验方式：公开的 Web App Demo 原型体验，以及团队主创使用真实数据和大语言模型的内部体验。

### A. Web App Demo 原型体验

#### 适用对象

评审、观众和普通体验者。

#### 体验地址

https://noneonnone.github.io/Robo-web-demo/

建议使用手机系统相机扫码，并在 Safari 或 Chrome 中打开。

#### 体验步骤

1. 打开 Web App Demo。
2. 在“今日”页面查看当日能量概况和身体时间线。
3. 点击底部录音入口，体验录音、转写、确认和编辑流程。如果没有开启麦克风，原型会使用演示文案继续流程。
4. 进入“地图”，查看一天中不同时间段的状态变化。
5. 进入“洞察”，查看系统如何呈现个人身体规律。
6. 进入“问问”，体验基于预设内容的个人问答交互。
7. 进入“我的”，查看数据权限和设备连接等产品设置。

#### 体验边界

Web App Demo 使用预置演示数据，主要用于展示产品逻辑、视觉设计和交互流程。

该版本：

- 不读取体验者的真实 HealthKit 数据；
- 不需要连接圆形硬件；
- 不会调用受限的大语言模型服务；
- 页面中的健康指标、记录、洞察和回答均为演示内容。

### B. 团队主创连接真实数据和大语言模型的体验

#### 适用对象

团队内部主创和指定演示人员。

#### 体验条件

- 安装内部版本 iOS App 的 iPhone；
- 已同步健康数据的 Apple Watch / HealthKit；
- 团队圆形硬件；
- 蓝牙、麦克风、语音识别、健康数据和本地网络权限；
- 已配置鉴权信息的内部开发版本。

#### 体验步骤

1. 由指定开发者在真机安装内部 iOS 版本。
2. 保持 iPhone 蓝牙开启，并确保 Apple Watch 的健康数据已经同步到 HealthKit。
3. 首次进入 App 后，在“我的—数据与隐私”中授权健康数据、麦克风、语音识别、蓝牙和本地网络访问。
4. 在数据与隐私页面扫描并绑定圆形硬件。
5. 通过圆形硬件发起真实麦克风音频流。手机接收音频后完成转写，并生成可以确认或编辑的记录。
6. 进入“今日”，确认刚刚生成的主观记录已经进入个人时间线。
7. 进入“地图”，查看基于真实 HealthKit 数据计算的个人能量状态。
8. 在“问问”中先测试本地问题，例如：
   - 我今天走了多少步？
   - 我昨晚睡了多久？
   - 我今天记录了几条？
   - 我最新的记录是什么？
9. 上述确定性问题由设备本地回答，不调用大语言模型。
10. 再由获得授权的开发者演示需要综合解释的问题，例如：“为什么我今天下午状态下降得比较快？”
11. 系统会将与当前问题相关、经过裁剪的个人上下文发送到受保护的服务端，并返回结构化回答、回答依据和实际调用路径。

#### 大语言模型权限说明

大语言模型服务已经加入 API Key 鉴权。目前只有组内负责开发的一人持有可用凭据，因此只有该开发者的内部版本能够调用真实的大语言模型。

其他团队成员、评审和公开 Web Demo 均不能直接调用模型服务。如需进行真实模型演示，应由该开发者使用已经配置好的设备现场操作。

鉴权信息不会出现在公开二维码、演示网页、截图或提交文档中。

## 六、数据与安全说明

### 1. 最小化上传

模型请求只包含与当前问题相关的摘要上下文。系统仅选取有限数量的近期记录，并限制文本和标签长度。

### 2. 原始数据不上送

服务端不会接收原始录音、完整语音转写、无关的 HealthKit 样本或整份设备本地数据库。

### 3. 模型密钥与客户端隔离

DeepSeek 密钥只保存在服务端，不会写入公开 Web Demo 或普通客户端。iOS App 通过独立的 Ask API Key 访问问答接口。

### 4. 回答路径可说明

系统会标记回答是否使用了设备本地数据、本地知识和大语言模型。当前版本没有接入在线外部搜索。

### 5. 非医学用途

SheRuntime 的洞察和回答仅用于个人回顾与学习，不用于疾病诊断、治疗建议或健康风险判定。

## 七、建议的现场演示顺序

建议先用 Web App Demo 在 2—3 分钟内讲清产品，再由指定开发者使用真实设备演示完整链路。

1. Web Demo：“今日 → 地图 → 洞察”，说明三类信息如何进入同一套个人身体学习系统。
2. Web Demo：“语音记录 → 问问”，说明低门槛记录和个人化交互方式。
3. iOS 真机：“HealthKit → 能量地图”，展示真实个人数据，而不是通用人群标准。
4. 圆形硬件：“录音 → BLE → 手机转写 → 时间线”，展示硬件与 App 的闭环。
5. “问问”页面：先演示本地问题，再由唯一获授权的开发者演示大语言模型归纳问题，并展示回答依据。

## 八、一句话总结

SheRuntime 不是告诉用户“你应该怎样”，而是把身体信号、真实感受和生活上下文组织起来，让用户逐渐学会读懂自己。
