# 13-规律引擎产品方案 v1（不同用户、不同数据，规律怎么算、怎么排、长什么样）

> 2026-08-29。回答 Ginger 的问题："不同用户数据不一样，规则的逻辑怎么写？优先展示什么？
> 解析的逻辑是什么？最终规则长什么样？"
> 地位：规律 tab 页（P1）的底层产品逻辑。数字门槛都是初版拍板值，Ginger 可改。
> 红线自查：本文档全部是"通用机制"——引擎是菜谱，不含任何具体用户的具体结论。

---

## 〇、一句话说清这台机器

**规律引擎 = 一台自动做菜的机器：看用户冰箱里有什么菜（数据），够做哪道就做哪道，
不够做的诚实说"还差什么"，并告诉她怎么补。**
换任何用户，机器一样，菜不一样。

---

## 一、输入端：用户的数据形态只有四种

| 形态 | 典型用户 | 引擎能干什么 |
|---|---|---|
| A. 什么都没有 | 刚下载，没手表也没开口 | 不算规律。给"通用背景"（明确标注：这是大多数人的知识，还不是你的）+ 三个补数据入口（见第五节） |
| B. 只有客观 | 有 Apple Watch，但不爱记录 | 能算：睡眠/心率/周期/日内地形/星期节律/异常日——够开出规律页大半内容；缺的是"为什么"（解释层），用"数据问诊"补 |
| C. 只有主观 | 没手表，但愿意说话/导日记 | 能算：情绪词频、主题周期、她自己报告的状态节律；缺的是身体佐证，鼓励接手表 |
| D. 都有（含缺项） | 理想态；缺项是常态不是例外 | 全菜单 + 主客观互相作证（最高级的规律：'你说累的那些天，身体数据也这么说'） |

**设计原则：缺数据永远不是报错，是引导。**引擎对每种缺失都有一句"补上 X，我就能帮你看 Y"——
这就是 01-M 的闭环：让用户知道说什么/戴什么最有用。

---

## 二、核心：每道菜的"开工门槛"表

五种配方（对比堆/周期相位/剂量梯度/日内地形/异常哨兵）+ 主观关联，每种都有硬门槛。
**门槛没到→这道菜不上桌，页面上也不出现半成品数字。**

| 配方 | 需要什么数据 | 至少多少 | 算出什么（举型） | 不够时对用户说什么 |
|---|---|---|---|---|
| ① 对比堆 | 睡眠+静息心率 | 30 天 | "连着睡够的日子 vs 没睡够的日子，你的身体差多少" | "再攒 X 天，我就能看出睡眠对你的真实影响" |
| ② 周期相位 | 经期记录+任一恢复指标 | 3 个完整周期 | "你的月经周期里，哪一段最容易累" | "记录满 3 次经期，我就能画出你的周期地形" |
| ③ 剂量梯度 | 入睡时刻+恢复指标 | 60 天 | "晚睡对你是渐变还是悬崖，悬崖在几点" | 同上句式 |
| ④ 日内地形 | 小时级心率 | 30 天 | "你一天里哪段省电、哪段费电" | "戴着手表过完这个月，你的一天地形图就出来了" |
| ⑤ 异常哨兵 | 腕温/呼吸/静息心率 | 28 天基线 | "哪些日子你的身体在打仗"（先有基线才谈异常） | 基线累计中，不提"异常"二字 |
| 星期节律 | 任一指标 | 8 周 | "你的一周里有没有固定的低谷日" | —— |
| 主观关联 | 主观记录+同期客观 | 14 条 | "你说 X 的那些天，身体数据通常 Y" | "多跟我说说，你的话每一句都会变成线索" |

配套纪律（引擎内置，不靠自觉）：
- 每条候选过**混杂核查**（知识卡 confounds 清单）
- **多重比较打折**：一轮扫了 N 个假设要如实记 N
- 探索性发现（不在假设清单里的）天花板 = "还在观察的线索"，重复出现才升级

## 三、输出端：优先展示的排序逻辑（三把尺子，按序用）

1. **当下相关**（第一优先）：今天用得上的先说。她正处在/即将进入某条规律的窗口
   （经前 X 天、连睡第 2 天…）→ 这条顶到首屏。规律页首屏永远只有这一条大卡。
2. **杠杆律**（第二优先）：窗口都不临近时，按"她数据里的效果 × 确定性 ÷ 做起来的成本"排四块里的顺序。
3. **新鲜优先**（第三）：刚升级/刚成立的规律，第一次露面时带一个"新"的仪式感，之后归队。

**数量刹车：**"我的规律"块默认最多展开 3 条，其余折叠。规律不是越多越好，是越被用上越好。

## 四、一条规律的一生（状态机——"最终规则长什么样"的动态答案)

```
[候选]──门槛没到──→ 页面上不存在（引擎内部记着）
   │ 达到门槛+方向初步成立
   ▼
[观察中]──→ 显示在"还在观察的线索"区："我注意到一个苗头，还需要 X 才能确认"
   │ 重复充分（≥10次/≥10周期）+混杂核查通过
   ▼
[成立]──→ 进"我的规律"，L1-L4 四层文案齐备，带三出口（看依据/试试看/问问它）
   │ 她真的试了+她的数据发生了预期变化
   ▼
[验证过]──→ 卡片长出"已被你的日子证实"标记，计入身体说明书（北极星+1）
   
任何状态──新数据推翻──→ [降级/撤回]：保留版本历史，诚实告诉她
   （"之前说的 X，最近的数据不再支持，我把它收回了"——敢改口是信任的一部分）
```

## 五、冷启动：数据不够时页面长什么样（= P3 留存设计的雏形）

**Day 0（形态A）**：三张卡
1. 通用背景卡（挑 1-2 条最有共鸣的，如"经前更累是普遍现象"——右上角永远标着"大多数人 · 还不是你的"）
2. 两个入口卡："接上 Apple 健康，身体开始替你说话" / "跟 Robo 说说今天，或把旧日记给我"
3. 种子花园入口（不依赖任何数据的情感留存——种下第一个渴望）

**Day 1-7**：进度感代替空白。"睡眠画像已收集 4/30 天"——像等一张照片显影，
每天打开都看见在长。绝不显示空图表。

**第一条规律诞生时**：这是产品的 aha 时刻，要有仪式感（IP 递上第一页说明书）。
门槛表里最快的一道菜（对比堆 30 天，或导入日记后当天）决定了 aha 来多快——
**日记导入是冷启动最大的加速器**（旧主观数据当天可用，配 F6）。

**客观数据先到位的用户**：触发"数据问诊"（01-I）——AI 挑 3 个她数据里的好奇点关切地问，
她的回答当场变成第一批主观数据。

## 六、实物样例：证据库 JSON 里一条规律长什么样

（结构是通用的；数值仅为示意格式，实际由引擎从每个用户数据算出）

```json
{
  "id": "cycle_premenstrual_recovery",
  "recipe": "周期相位",
  "status": "成立",
  "gate": { "需要": "3个周期", "实际": "22个周期", "通过": true },
  "混杂核查": { "已排除": ["入睡时刻"], "未排除": ["工作强度"] },
  "样本": { "天数": 152, "周期数": 22 },
  "文案": {
    "L1": "每次月经来之前的那一周，你会比平时更容易累……（人话+比喻+伞）",
    "L2": "过去两年多的22个周期里，你的三个恢复信号几乎每次都一起变差……",
    "L3": { "图表数据": "…数字只活在这一层…" },
    "L4": { "文献": "方向与已有研究一致", "链接": "…" }
  },
  "当下相关": { "类型": "周期窗口", "下次触发": "经前7天自动置顶" },
  "杠杆分": 8.5,
  "出口": {
    "试试看": { "种子": "把要紧的事挪出经前窗口" },
    "问问它": { "预填": "关于经前更容易累这件事，我想问…" }
  },
  "历史": [ { "日期": "…", "事件": "从观察中升级为成立" } ]
}
```

**分工**：数字由确定性代码算（艾瑞的分析引擎，15 段恢复脚本是原型）；
L1/L2 文案由 AI 按 prompt 生成，但**必须过五关质检**（独立质检环节，不靠生成 AI 自觉）；
页面只负责渲染这个 JSON——三层各司其职。
