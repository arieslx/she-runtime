# body-knowledge：身体观察知识库

## 这个知识库是什么

供产品/设计/开发共用的**证据索引**，不是诊断指南、不是全文语料包。
两类卡片，都在 `knowledge/` 下：

- `knowledge/metrics/METRIC-*.md` —— 指标知识卡（8 张）：每个 Apple Health 指标一张，
  含可检验假设清单（analysis_hypotheses）、混杂坑（confounds）、安全措辞（safe_claim/avoid_claims）
- `knowledge/papers/*.md` —— 论文卡：单篇文献的摘要级结论与措辞边界
  （架构见 https://arieslx.github.io/2026/08/26/body-knowledge-papers/）

## 检索规则（生成用户可见内容时）

1. 按指标或 trigger_tags 找到相关卡
2. **只取用：source_id + safe_claim + avoid_claims + action_type**，不要整段搬运卡片正文
3. 生成的文案必须：
   - 服从卡里的 avoid_claims（禁用措辞绝对不出现）
   - 口径="可能同时出现，值得观察"，不说"就是因为"
   - 通用知识标注为通用背景，不冒充用户的个人规律
   - 个人规律必须来自用户自己数据的统计，引用时带样本量
4. 危险信号（胸痛/呼吸困难/晕厥/大量出血伴虚弱/剧痛快速加重）不走知识卡，直接建议就医

## 数据分析时（挖掘个人规律）

1. 从对应 METRIC 卡的 `analysis_hypotheses` 取假设清单——这是"往哪看"
2. 检验前过一遍该卡 `confounds`——这是"别上当"
3. 每条发现按证据阶梯标注（L1 方向与文献一致 → L2 多指标交叉 → L3 重复≥10次
   → L4 盲测通过 → L5 前瞻预测命中 → L6 用户确认 → L7 用户实验验证）
4. 探索性发现（不在假设清单里的）天花板是"新线索"，须再现才升级

## 新增/修改卡片的规矩

1. **没有 avoid_claims 的内容不进库**（硬规则）
2. 引用必须真实可查（PMID/DOI/URL），不确定就标"待核"，禁止编造
3. 优先级：P1 系统综述/荟萃 | P2 叙述综述/观察/单RCT | P3 小样本（P3 只用于提出观察问题）
4. 每季度复查；新旧结论冲突时保留版本、降低触发强度
5. 全文 PDF 只存开放获取的；非 OA 只存元数据+摘要级总结

## 与产品规则的关系

本知识库管"说什么有依据"；AI 的行为方式（何时主动/如何反馈/表达格式）
由产品侧《01-AI行为规则》约束，做 prompt 时两者都要接。
